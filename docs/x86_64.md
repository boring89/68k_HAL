# x86-64（64 位元）移植

`arch/x86_64/`、`platform/pc/boot/boot64.asm`、`linker64.ld`、Makefile 的 `ARCH=x86_64`

目標：kernel 能使用 P520 的 64 GB 記憶體與 4 GiB 以上的裝置位址（xHCI、HDA 的 BAR 在 `0x43ffff…`）。
32 位元的建置在移植期間保持可用（`make`、`make test`）；64 位元用 `make ARCH=x86_64`，輸出到 `build/x86_64/`。

這份文件在 S9 會補上位址空間圖、開機流程與遇到的問題；現在只有 S0 的盤點。

## 1. 移植清單（S0）

### 1.1 已經與位元數無關（用 `-m64` 編譯 kernel/、drivers/、emu/、platform/ 只有 4 個警告，已修）

- `kernel/` 的指標與位址一律用 `uintptr_t`；`hal/` 的介面（`hal_mmu_map(uintptr_t, uintptr_t, ...)`）、PMM 的 API 也是。
- PCI BAR 的解碼（`platform/pc/pci/pci_bar.c`）本來就支援 64 位元 BAR；只有 `hal_pci_map_bar` 與 `vmap` 擋掉 4 GiB 以上。
- Musashi 與 `emu/` 在 host 測試時就是 64 位元。

### 1.2 S0 已改的共用程式碼

| 位置 | 改了什麼 |
|---|---|
| `hal/mmu.h` | 新增 `hal_phys_to_virt()`：32 位元是 identity，64 位元（`-DHAL_PHYS_BASE`）加上 HHDM 的位移 |
| `platform/pc/boot/multiboot.c`、`hal_boot.c` | Multiboot 結構裡的位址都是實體位址，一律經 `hal_phys_to_virt` 讀；Multiboot2 轉出的表（在 kernel 映像裡）用實體位址 `image_phys()` 放進 32 位元欄位；新增 `multiboot_info_phys()` |
| `kernel/mac`、`kernel/user/process.c`、`kernel/block/ramdisk.c` | 開機 module 的內容用 `hal_phys_to_virt(module.base)` 取得指標，不再直接把實體位址轉成指標 |
| `kernel/memory/memory.c`、`arch/x86/interrupt/idt.c`、`kernel/user/process.c` | 指標轉 `uint32_t` 的地方先轉 `uintptr_t` |

### 1.3 必須為 64 位元重寫的部分（`arch/x86_64/`、`platform/pc/`）

| 區域 | 32 位元的假設 | 64 位元的做法 |
|---|---|---|
| 開機 `platform/pc/boot/boot.asm`、`linker.ld` | 保護模式進入點、kernel 放在 1 MiB、identity mapped | 32 位元進入程式：建立開機頁表、PAE、`EFER.LME`、開分頁、載入 64 位元 GDT、跳到 higher half |
| GDT/TSS `arch/x86/gdt` | 8 位元組描述元、32 位元 TSS（`esp0`） | 64 位元 GDT（含 16 位元組的 TSS：`rsp0`、IST）；保留 32 位元 user code segment（compatibility mode） |
| IDT 與例外 `arch/x86/interrupt` | 8 位元組閘、`pusha`、`interrupt_frame` 是 32 位元暫存器 | 16 位元組閘、手動 push 15 個暫存器、新的 `interrupt_frame` |
| 分頁 `arch/x86/mmu` | 2 層、4 MiB 一個 PDE、遞迴映射、`space.c` 用視窗編輯別的行程的目錄 | 4 層頁表，透過 HHDM 直接存取任何頁表；kernel 半邊（PML4 的 256–511）所有行程共用；低半邊是行程私有 |
| context switch `arch/x86/task` | 保存 edi/esi/ebx/ebp，`hal_context_t.sp` 是 `uint32_t` | 保存 rbx/rbp/r12–r15，`sp` 是 `uint64_t` |
| 使用者模式 `arch/x86/user` | `iret` 到 ring 3、`int 0x80` | 一樣用 `iretq` 到 32 位元 user code segment（compatibility mode），`int 0x80` 經 64 位元 IDT；i386 程式不用重編 |
| `arch/x86/cpu/cpu.h` | `cpu_read_cr*` 回傳 `uint32_t`、`pushfl` | 共用，改成 `uintptr_t`、`pushf` |
| AP 啟動 `platform/pc/smp/trampoline.asm` | 真實模式 → 保護模式後呼叫 C | 其他處理器只回報後 `hlt`（沒有 per-CPU 資料），所以在保護模式用組語遞增計數器後停住 |
| `platform/pc/vmap` | 視窗在 `0xE0000000`、拒絕 4 GiB 以上 | 視窗放在 kernel 半邊，BAR 可在任何實體位址 |
| `platform/pc/dma` | 實體位址 `uint32_t`、PMM 只有 4 GiB | DMA 記憶體仍然要求在 4 GiB 以下（`pmm_alloc_frames_below`） |
| PMM `kernel/memory/pmm.c` | bitmap 固定 4 GiB（128 KiB） | bitmap 涵蓋 128 GiB（4 MiB，在 .bss） |
| kernel 的位址常數 | `HEAP_VIRT_BASE 0x20000000`、`M68K_GUEST_RAM_BASE 0x10000000` 在低 4 GiB | 64 位元移到 kernel 半邊（低半邊整個留給使用者程式） |
| `platform/pc/hal_init.c` | `map_boot_data` identity map 開機資料 | 不需要：HHDM 涵蓋所有 RAM |
| `platform/pc/power` | `lidt` 的描述元 6 位元組 | 64 位元是 10 位元組 |
| 測試 `arch/x86/test/selftest_x86.c` | 分頁測試依賴遞迴映射與 identity map | 64 位元版另寫（`arch/x86_64/test/`） |
| Makefile | `-m32`、`nasm -f elf32`、`ld -m elf_i386`、`qemu-system-i386 -kernel` | `ARCH=x86_64`：`-m64 -mcmodel=kernel -mno-red-zone -mno-sse…`、`elf64`、`elf_x86_64`；QEMU 的 `-kernel` 只吃 32 位元 ELF（Multiboot 1），所以用 `objcopy -O elf32-i386` 轉換 |

### 1.4 不改

- 使用者程式（i386 靜態 Linux 程式）繼續跑，不重編（見計畫的設計決定）。
- Musashi（不可修改）：kernel 版用 `-m64` 另編，使用 `emu/m68k/freestanding/` 的替身 libc。
