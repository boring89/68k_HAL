## 實機結果與 P8 的修正（2026-10-17 第一次實機測試）

第一次實機測試（UEFI 開機）：開機、ACPI、I/O APIC、TSC、12 顆 CPU、AHCI、e1000e（I219，link up）、PS/2（韌體的 USB→PS/2 模擬）、診斷選單、Mac 開到桌面都正常。回報的問題與 P8（自動排程，**只在 QEMU／host 驗證，沒有實機驗證**）的處理：

| 問題 | P8 的處理 | 實機要看什麼 |
|---|---|---|
| xHCI（8086:a2af）、HDA（8086:a2f0）的 BAR 在 4 GiB 以上（`0x43ffff10000` 等） | **kernel 改成 64 位元（預設）**，`vmap`／`hal_pci_map_bar` 不再拒絕 4 GiB 以上；`lspci -v` 印 16 位數的 64 位元 BAR。QEMU+OVMF 無法讓 BAR 落在 4 GiB 以上，所以 xHCI 在高位址的行為只能實機驗證 | `usb` 是否列出鍵盤滑鼠、是否還需要韌體的 PS/2 模擬；**BIOS 的 Above 4G Decoding 不需要再關閉**（64 位元 kernel 看得到 4 GiB 以上，也能用全部 64 GB 記憶體） |
| NVMe（bus 0x17）與 GTX 1070（bus 0x65）沒被列舉 | PCI 掃描所有 bus（bus 1–255 也掃，已經經由橋掃過的略過），裝置上限 256；`make test-pci-roots`（q35 + pxb-pcie）檢查 | `lspci` 是否出現 NVMe 2646:5013 與 GTX 1070（10de:1b81）；`disks` 是否列出 `nvme0` |
| Mac 畫面不到 5 fps、診斷頁捲動有殘影 | framebuffer 改用 **PAT write-combining**（`HAL_MMU_WRITE_COMBINING`；韌體的 MTRR 把顯示記憶體設成 UC，UC + PAT WC = WC，Intel SDM Vol.3A 11.12）；Mac 只更新有變動的列且不從螢幕讀；fbcon 跳過沒變的格子 | 開機訊息有 `Framebuffer memory: write combining`；Mac 結束後印**效能數據**（frames/s、每格模擬時間、每秒百萬指令、每次更新的列數）——**請拍照回報**，也可用 `dmesg` |
| Mac 執行時 kernel 訊息蓋住畫面 | Mac 佔用畫面時 fbcon 不畫（訊息照進 `dmesg` 與 serial），結束後重畫原本的畫面與文字 | 開 Mac 時畫面乾淨；結束回到 `HAL>` 後文字還在 |
| 開 Control Panels → Monitors 或開多個程式時卡死 | **原因查明並修正**（`emu/mac`）：空的 NuBus slot 被當成有卡，System 建了 16 個 GDevice，Monitors 控制台的 16 格陣列越界。現在開機後只有 1 個 GDevice（`make test-rom` 檢查），Monitors 在 host 上能打開（`docs/mac.md` 第 4 節） | 開 Monitors、再多開幾個程式 |
| 滑鼠游標移出畫面後回不來 | 是上一項卡死的結果：host 上用極端移動封包測過，游標會夾在螢幕邊並回得來 | 同上；若仍發生請回報（實機是韌體的 PS/2 模擬，可能另有原因） |
| 解析度只有 800x600 | `grub-usb.cfg` 的 UEFI 項目載入 `kernel-gfx1080.elf`（Multiboot2 header 要求 1920x1080；螢幕沒有這個模式時 GRUB 保留韌體的模式），最後多一個「保留韌體解析度」的項目；`make test-usb-image` 檢查兩種 | 解析度是否變成 1920x1080（或螢幕的原生解析度）；不行就選「保留韌體解析度」 |

另外：**64 位元 kernel 的其他處理器仍只啟動後 `hlt`**（和以前一樣）；`cpuinfo` 的 `CPUs online` 照舊。

（P7 R8，自動排程一次做完。**所有東西都只在 QEMU 驗證過，沒有在實機執行過**，所以這份清單的目的就是把實機的結果帶回來。）

## 0. 先講安全

- 這個 OS 只讀寫**隨身碟上的映像**，不會碰你電腦的硬碟（也不會自動掛載它）：NVMe（Kingston KC3000）與 SATA 驅動只在你用 `disks`、`ls`/HFS 指令時才讀；kernel 不會自動寫它們。測試期間保險起見，**可以暫時拔掉資料碟的 SATA 線，或者不用管它**——程式裡沒有任何自動寫硬碟的路徑（寫入只有 `block_write`，由使用者程式或 Mac 的磁碟映像明確觸發，而 Mac 的磁碟是 boot module 的 RAM 副本）。
- 映像由**你自己**寫進隨身碟。下面的 `dd` 會**清掉隨身碟**，請確認裝置名稱（用 `lsblk`），**寫錯裝置會毀掉那個裝置的資料**。

## 1. 產生並寫入映像

```bash
make usb-image        # 產生 build/68k_HAL_usb.img（BIOS/CSM 與 UEFI 都能開機）
# 想在實機上跑 Mac：把你自己的 ROM 與磁碟映像放進去（只放在這個本機映像；不要分享這個映像）
make usb-image MAC_ROM="$HOME/mac/.../368CADFE - Mac IIci.ROM" MAC_DISK=$HOME/mac/System7_5_3.img
```

找到隨身碟（插上後執行，看新出現的裝置與大小；確定不是你的系統碟）：

```bash
lsblk -o NAME,SIZE,MODEL,TRAN,MOUNTPOINT
```

寫入（把 `sdX` 換成隨身碟，例如 `sdb`；不是 `sdb1`）：

```bash
sudo umount /dev/sdX* 2>/dev/null
sudo dd if=build/68k_HAL_usb.img of=/dev/sdX bs=4M conv=fsync status=progress
sync
```

映像是 ISO 9660 的混合映像（hybrid）：前面有 MBR 讓 BIOS 開機，後面有 EFI 系統分割讓 UEFI 開機，所以同一個隨身碟兩種模式都可以。

## 2. BIOS／UEFI 設定（開機時按 F1 進 Setup；P520 的 Lenovo BIOS）

- **先用 UEFI 試**（建議，解析度與 ACPI 都最完整）：Startup → Boot Mode / UEFI/Legacy Boot = **UEFI Only**（或 Both，UEFI first），**Secure Boot 關閉**（`Security → Secure Boot → Disabled`；我們的 GRUB 沒簽章）。CSM（Compatibility Support Module）關閉。
- **再用 CSM（傳統 BIOS）試**：UEFI/Legacy Boot = **Legacy Only**（或開 CSM），這時 GTX 1070 會用 VBIOS 的 VGA 文字模式／VBE。
- **Above 4G Decoding（4G 以上解碼）不需要關閉**（P8 起 kernel 是 64 位元，看得到 4 GiB 以上的位址；用 32 位元建置 `ARCH=i386` 時才需要關閉，否則 BAR 在高位址的裝置會看不到，開機訊息：`NVMe: its registers are not reachable`）。
- x2APIC 不需要關：kernel 會自己把 local APIC 切回 xAPIC 模式。
- 開機選單：開機時按 **F12**，選隨身碟；UEFI 與 Legacy 的項目通常分開（名稱有 "UEFI:" 前綴的是 UEFI）。
- 鍵盤：兩種模式都用 USB 鍵盤。UEFI 模式下 BIOS 的 USB 支援會把鍵盤交給 GRUB；進入我們的 kernel 後，由 kernel 自己的 xHCI 驅動接手（沒有 PS/2）。如果進了 kernel 之後鍵盤沒反應，這是第一個要回報的問題（見 §5）。

## 3. GRUB 選單（15 秒內不選就開機第一項）

| 項目 | 做什麼 |
|---|---|
| `68k_HAL` | 一般模式：APIC 中斷、所有 CPU 核心、xHCI USB。BIOS 是 VGA 文字模式；UEFI 是 framebuffer 文字終端 |
| `68k_HAL - safe mode (noapic nosmp)` | 安全模式：舊的 8259 中斷、只用一顆 CPU、MSI 不開。**如果一般模式當掉或沒有鍵盤，用這項重試**，兩者的差別就是線索 |
| `68k_HAL - hardware diagnostics` | 依序顯示 cpuinfo、acpi、lspci -v、usb、irqs（每條中斷線的計數）、disks、net、開機訊息（前半、後半），每頁停 10 秒或按任一鍵下一頁。**每頁拍一張照片** |
| `68k_HAL - Macintosh (graphics, then type: mac)` | 圖形模式（P9 起要求 2560x1440，BIOS 與 UEFI 都是），進入後打 `mac` + Enter（需要你放了 ROM 與磁碟） |
| `68k_HAL - diagnostics without the USB driver (noxhci)` | 同診斷，但不啟動 xHCI 驅動。**一般模式當掉或沒有鍵盤時**：這項會自己翻頁，能分辨是不是 USB 驅動的問題（診斷頁的 `usb` 只列出控制器） |
| `68k_HAL - graphics console (BIOS, 640x480)` | 只有 BIOS 模式有：640x480 的圖形主控台 |
| `68k_HAL - UEFI: 1920x1080` | 只有 UEFI 有（P9）：要求 1920x1080 |
| `68k_HAL - UEFI: keep the firmware's resolution` | 只有 UEFI 有：不要求解析度 |

## 4. 要檢查什麼（每一項，依序）

每一項請記下：**成功／失敗／不確定**，失敗時拍照。進入後的提示是 `HAL>`。

| # | 項目 | 怎麼測 | 成功的樣子 |
|---|---|---|---|
| 1 | 開機到 shell | 選 `68k_HAL` | 畫面出現 `HAL>`（UEFI：解析度與螢幕相符、字有放大） |
| 2 | 開機訊息 | `dmesg` | 沒有 `[ERROR]`／`panic`；注意 `Loader framebuffer: …`、`Interrupts:`、`xhci:`、`nvme:`、`e1000e:` 幾行 |
| 3 | CPU 與 ACPI | `cpuinfo`、`acpi` | 6 核 12 執行緒的 Xeon W-2135（`CPUs online` 12 或 6）；`Interrupts: IOAPIC`；有 override |
| 4 | PCI | `lspci -v` | 看到 xHCI 8086:a2af、NVMe 2646:5013、AHCI 8086:a282、I219 8086:15b7、HDA、GTX 1070（10de:1b81）、IOAPIC |
| 5 | USB 鍵盤與滑鼠 | 鍵盤打字、移動滑鼠（打 `run /bin/evtest` 看事件，Q 結束）、`usb` | `usb` 列出鍵盤（`keyboard`）與滑鼠（`mouse`）。鍵盤接在 hub（螢幕或擴充座）後面也支援（QEMU 驗證過 USB2 hub，SuperSpeed hub 沒測過）；如果接 hub 後面沒反應，請改直接插機殼後面的 USB 埠再試 |
| 6 | NVMe | `disks` | 列出 `nvme0`，大小與 KC3000 相符（這是**唯讀測試**：只要看 `disks`；`ls`/`cat` 只讀 HFS 映像） |
| 7 | SATA | `disks` | 如果接了 SATA 碟，列出 `sata0` |
| 8 | 網路 | 接上網路線，`net`、`dhcp`、`ping <閘道>`、`dns example.com` | `net` 顯示 e1000e、MAC、link up；`dhcp` 得到位址；ping 有回覆。**I219 是最不確定的一項**（見下） |
| 9 | 聲音 | `beep` | 從主機板的喇叭／耳機聽到嗶聲（HDA 的輸出路徑是否選對了不確定） |
| 10 | 圖形與 Mac | 選 Mac 項目，`mac` | Mac 桌面出現，置中並放大（P9：依螢幕自動選 Mac 的解析度與倍率，見上面的 P9-2），用 USB 滑鼠與鍵盤操作（Alt = Command） |
| 11 | 安全模式 | 選 safe mode，重做 1、3、5 | 一般模式失敗時，看安全模式能不能開機 |
| 12 | 多工 | `seq 1000 \| grep 7 \| wc -l`；`sleep 30` 之後 Ctrl-C | 輸出 271；Ctrl-C 後出現 `[exit 130]` |

**結束**：在 `HAL>` 打 `poweroff`（ACPI 軟關機；失敗會印 `It is safe to turn off the computer.` 然後停住，這時長按電源鍵）或 `reboot`。`acpi` 指令的 `Soft off:`／`Reset:` 兩行說明用哪一種方式。

## 5. 怎麼回報結果

最有效的是**拍照**（手機拍螢幕就行），然後告訴 Claude：用的是 **UEFI 還是 CSM**、選的是哪個選單項目、第幾項（上表編號）怎樣。照片裡最有價值的是：

- 診斷項目的每一頁（`hardware diagnostics`，自動換頁，每頁 10 秒；想停久一點就不要按鍵，快一點就按任一鍵）；
- 螢幕全黑或當掉時的最後一個畫面（有 `panic`、`fault`、`Loader framebuffer: … (not usable)` 的字樣）；
- `dmesg` 的輸出（最後 20 行：`dmesg 20`）。

如果**螢幕全黑**：UEFI 模式下表示 GRUB 給的 framebuffer 我們用不了（顏色格式不是 BGRX，或位址在 4 GiB 以上）；請改試 CSM，並說明。如果**有畫面但鍵盤沒反應**：先換一個 USB 埠（機殼後面，直接接主機板，不經 hub）；再試 safe mode；仍不行請拍 `dmesg`（看 `xhci:` 與 `usb:` 行）。如果**開機到一半重開機**：很可能是 triple fault，請拍最後的畫面，並用 safe mode 重試。

## 6. 每個硬體目前的支援狀態

| 硬體 | 狀態 | 備註 |
|---|---|---|
| 開機（UEFI／CSM） | QEMU 驗證 | Multiboot2＋UEFI（GOP framebuffer）；CSM 走 Multiboot 1（文字或 640x480） |
| CPU（Xeon W-2135） | 已有的功能 | 64 位元 kernel 可用全部 64 GB 的 RAM；其他核心只啟動後 `hlt` |
| 中斷（LAPIC／IOAPIC／MSI） | QEMU 驗證 | 實機有 IOAPIC 8086:2026；`noapic` 是退路 |
| USB 鍵盤滑鼠與隨身碟（xHCI 8086:a2af） | QEMU 驗證 | hub 只驗證過 USB2；隨身碟會成為區塊裝置 `usb0`（`disks` 列出，開機用的那支也會被列出）；實機的 BIOS 交接（legacy support）是第一次碰到真實控制器 |
| NVMe（Kingston KC3000） | QEMU 驗證 | 輪詢、namespace 1；KC3000 的實際相容性未知 |
| SATA（AHCI 8086:a282） | QEMU 驗證 | 既有驅動，輪詢 |
| 網路（I219-LM） | **未驗證**（QEMU 只驗 82574L） | PHY、ULP、Management Engine 可能造成 link down，見 docs/net.md |
| 聲音（HDA 8086:a2f0、GTX 的 HDMI 音訊） | QEMU 驗證 | 實機的 codec 與輸出腳位可能不同，`beep` 可能沒聲音 |
| 顯示（GTX 1070） | 只用韌體的 framebuffer | 不寫 NVIDIA 驅動；解析度是韌體選的 |
| 序列埠 | 沒有 | P520 的 UART 是 Intel LPSS（MMIO），不是 0x3F8，所以實機沒有序列埠輸出，除錯只靠畫面（`dmesg`、`diag`）與照片 |
| 其他（Thunderbolt、藍牙、Wi-Fi…） | 不支援 | |
